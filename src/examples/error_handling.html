Error Handling & Validation

Shows where TronDesigner reports problems and how to react to them in your code.

  • openDesigner() and open() return nothing - don't chain .then() / .catch(). Problems with the editor arguments or the product data show the editor's error dialog; closing it calls onClose('Error').
  • Before (or after a failed) initialization the open methods only log an error to the console - check getInitialized() first. Initialization failures are shown in the Init Failure Handling example.
  • Invalid custom buttons make setEditorButtons() / addEditorButton() throw synchronously.
  • Methods that call the API (getPrintJob(), getProofreading(), clonePrintJob(), ...) return a promise that rejects when the request fails.
  • There is no error event. Open the browser console (or set data-td-log-level="debug") for details.

Error Handling Patterns

1. Check that the script is ready

const td = window.tronDesigner;
if (!td?.getInitialized()) {
    showError("The designer is not available right now.");
    return;
}

// or wait for it (rejects when the initialization fails)
try {
    await window.tronDesigner.getInitializing();
} catch (error) {
    console.error("TronDesigner failed to initialize", error);
}

2. Editor errors: the onClose callback

td.openDesigner(editorArguments, {
    mode: "dialog",
    onClose: (reason) => {
        // 'Confirmed', 'Cancelled' or 'Error'
        if (reason === 'Error') showError("The designer could not be loaded.");
    }
});

3. Synchronous errors: invalid custom buttons

try {
    td.setEditorButtons(buttonsFromConfig) // throws before anything else is added to the builder
        .setExactProduct('PFC', undefined, (b) => b.addVariant('10086021'))
        .addExactPrinting('front', 'PAD03')
        .open({ mode: "dialog" });
} catch (error) {
    console.error("Could not open the designer", error);
}

4. API calls: promise rejection

try {
    const printJob = await td.getPrintJob(printJobGuid);
} catch (error) {
    console.error("Print job could not be loaded", error.message, error.cause);
}
