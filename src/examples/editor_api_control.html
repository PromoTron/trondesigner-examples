Editor API – Controlling the editor

openDesigner() returns the running editor. Your page calls its commands: show a colour or a printing, check the design, save, read the saved print job, generate the proofreading, download images, close the editor. Every command returns a promise and fails with an error code; the log below shows the calls, the results, the errors and the editor's td… events.

Try: open the editor, add a logo or a text, then Save and Get saved print job. Get saved print job before the first save fails with INVALID_STATE, and the unknown technique with NOT_FOUND.

Implementation Notes

  • openDesigner() (and the builder's open()) resolve to the editor element as soon as it is in the page, or to null when it did not open; they never reject. window.tronDesigner.getActiveDesigner() returns the editor opened last.
  • Wait with await editor.whenReady() or the tdReady event; commands called earlier wait up to 60 seconds and then fail with NOT_READY.
  • getPrintJob() returns the print job as it was last saved - call savePrintJob() right before it.
  • Changes and saves run one at a time: a second one while the first is running fails with BUSY.
  • Check editor.supports(command) before relying on a newer command: the editor is loaded from TronDesigner and can be newer than your code.

Code Example:

const editor = await tronDesigner.openDesigner(editorArguments, {
    mode: "container",
    container: document.getElementById("editor-container")
});
if (!editor) return; // did not open - see the console

await editor.whenReady();
if (!(await editor.hasMotive())) return showMessage("Add a logo or a text first.");

try {
    await editor.savePrintJob();
    const printJob = await editor.getPrintJob(); // code, printings, image URLs
    addToCart(printJob.printJobGuid, printJob.code);
} catch (error) {
    if (error.code === "BUSY") return; // another save is running
    throw error;
}
